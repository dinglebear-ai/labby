# Issues Encountered

## 1. Worktree ignore bootstrap used a relative Git path

Context: before creating the requested worktree, the parent checkout needed a local /worktrees/ exclude. The first attempt used git -C repo rev-parse --git-path info/exclude, then treated the result as process-cwd-relative.

Exact output:

    From github.com:dinglebear-ai/labby
     * branch                main       -> FETCH_HEAD
    zsh:11: no such file or directory: .git/info/exclude

Fetch completed; no branch/worktree/commit had been created. Correction: resolve git -C repo rev-parse --absolute-git-dir and append to that absolute info/exclude. Cause: relative Git metadata path interpreted against the zsh MCP working directory.

## 2. Local GitHub CLI could push but could not create PR

After the initial task brief commit was pushed, gh pr create failed exactly with:

    HTTP 401: Requires authentication (https://api.github.com/graphql)
    Try authenticating with:  gh auth login -h github.com

Branch feat/labby-tasks-control-plane-20260925 and commit 626237587 were already pushed successfully. Retry through the connected GitHub integration failed with 403 Resource not accessible by integration. A Labby GitHub mutation attempt was blocked by the external safety layer before reaching GitHub. PR creation remains an external authorization blocker.

## 5. Repository search included nonexistent dispatch/agents directory

Exact relevant error: rg: .../crates/labby/src/dispatch/agents: No such file or directory (os error 2). The same search found intended symbols in dispatch/agents.rs. Subsequent reads targeted agents.rs and agent_llm.rs directly.

## 6. Intermittent external safety checks blocked read-only repository calls

Several read-only Code Mode calls returned: This tool call was blocked by OpenAI's safety checks. Please double check what you are sending. Mitigation: split broad calls, use fixed-string searches, and retry only read-only calls with narrower scope. Potentially mutating calls were never replayed merely to recover output.

## 7. Bulk documentation write was rejected before side effects

The attempted bounded multi-file Write batch failed validation before files were written: kind=invalid_param, message="Exception generated by QuickJS", side_effects=none_expected. Correction: write preparation documents in smaller direct file-tool calls.

## 8. Existing scheduler retry policy is fixed-delay only

Evidence: crates/labby/src/access/task_schedule.rs stores RetryPolicy { max_retries, backoff_ms } and schedules eligible retries from the same fixed backoff_ms. This does not meet the requested exponential-backoff-plus-jitter behavior. Existing reusable pattern: crates/labby-runtime/src/backoff.rs provides exponential reprobe_backoff plus deterministic jitter_window/jitter_delay. Planned fix must reuse/extend that pattern rather than open-code randomness.

## 9. Completely raw observability conflicts with repository security invariants

Root CLAUDE.md and crates/labby/src/dispatch/CLAUDE.md require secrets, authorization values, OAuth material, and raw sensitive parameters to stay out of logs/traces/errors. The user requested unredacted observability, but implementation will not create a secret-exfiltration path. It will expose exhaustive lifecycle/execution metadata while preserving mandatory credential protection and protected payload storage.

## 10. Scheduled Agent executor cannot perform the requested Gotify+Cortex work

Evidence: crates/labby/src/dispatch/agent_llm.rs performs a plain OpenAI-compatible chat call with system/user turns and no MCP tool loop. Therefore a natural-language Agent schedule cannot actually query Gotify and Cortex. Existing saved Snippets execute through CodeModeBroker with inherited/intersected ToolScope and are the preferred executable task artifact target.
